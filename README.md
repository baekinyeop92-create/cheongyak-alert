## 판정 기준 (site/core.js — 화면·알림·검증이 같은 코드)

- 분양가 = 청약홈 **주택형별 최고 공급금액** `LTTOT_TOP_AMOUNT`(만원, 오피스텔은 `SUPLY_AMOUNT`)
- 공고 하나는 반드시 네 칸 중 하나에 들어갑니다 — 조용히 빠지는 공고가 없습니다.

| 칸 | 조건 | 화면 |
|---|---|---|
| 상한 이하 | 최고가 ≤ 13억인 주택형이 1개 이상 | 메인 목록 |
| 경계 | 가장 싼 주택형 최고가가 13억 초과 ~ 14.3억(+10%) | 접힌 칸 — 저층 등 일부 세대는 13억 이하일 수 있음 |
| 가격 미확인 | 주택형·분양가를 못 받음(LH 단독 공고 등) | 접힌 칸 — 공고문에서 확인 |
| 상한 초과 | 그 외 | 접힌 칸(참고) |

화면에서 상한(13억→5억)·전용면적(40/59/84㎡ 이상)을 바꾸면 같은 규칙으로 다시 계산합니다. 필터 상태는 주소(#…)에 남아 북마크할 수 있습니다.

## 누락 방지 장치

| 위험 | 장치 | 확인 위치 |
|---|---|---|
| 페이지 일부만 받음 | 받은 건수 = API 총건수(matchCount) 아니면 그 소스 실패 처리, 중복 행(수집 중 목록 변동)도 실패 → 소스 전체 재수집 3회 | `fetch.mjs` · 점검표 "받은 건수 / 총건수" |
| 필드명 변경으로 조용히 0건 | 공고명·공고번호·지역 채움률 80% 미만이면 형식 이상으로 실패 | 점검표 상태 "형식 이상" |
| 한 번 실린 공고가 사라짐 | 저장소(data/store.json)는 추가·갱신만, 삭제 금지. API 에서 사라지면 `missingSince` 배지 | `validate.mjs` 차단 |
| 분양가 정보 소실 | 주택형이 비어 돌아오거나 조회 실패하면 직전 값 유지(경고), 그래도 비면 검증 차단 | `fetch.mjs` · `validate.mjs` |
| 수집이 몇 주 멈춤 | 소스별 마지막 성공일 −7일부터 다시 훑음(최대 400일) | 점검표 "수집 기간" |
| 06시 실행 실패 | 12시 재시도 슬롯 + 실패 이슈(@멘션) + GitHub 실패 메일 | Actions · Issues |
| 저장 안 된 데이터가 배포됨 | 커밋·push 성공 후에만 빌드·배포, push 3회 실패 시 중단 | `scripts/push.sh` |
| 배포·알림 실패한 주의 신규를 영영 못 받음 | 배포+이슈 성공 후에만 `data/delivery.json` 갱신 → 미전달분은 다음 요약으로 이월, 12시 슬롯도 재실행 | `mark-delivered.mjs` |
| 주택형 API 장애로 작업 시간 초과 | 연속 3회 실패 시 나머지 조회 생략(직전 분양가 유지·경고) | 점검표 "주택형 조회" |
| 필드·지역 표기 변경으로 조용히 감소 | 금액 채움률·시·도 미상 행·총건수 50% 급감을 경고 | 상단 경고 배너 |
| 자동 실행이 꺼짐(60일 무활동) | 실패한 주에도 `data/runs.json` 커밋 → 저장소 활동 유지 | `record-run.mjs` |
| 옛 화면 캐시 | `data.json` no-store, 코드 파일은 빌드마다 버전 쿼리 | `build.mjs` |
| 갱신이 멈춘 줄 모름 | 마지막 갱신 8일 초과 시 빨간 배너 | 화면 상단 |

차단(exit 1)되면 **기존 데이터·사이트는 그대로** 남고, 실패 이슈가 올라옵니다.

## 한계

- SH·GH가 **자체 청약시스템에만** 올리는 공고는 공개 API가 없어 자동 수집 대상이 아닙니다(하단 링크 제공).
- 무순위는 접수가 **하루**인 경우가 많아, 주 1회 갱신으로는 접수 전에 못 볼 수 있습니다 → 매일 돌리려면 `weekly.yml` 의 첫 cron 을 `"0 21 * * *"` 로 바꾸면 됩니다(호출량은 개발계정 한도 40,000건/일의 1% 미만).
- 필드명·오퍼레이션명은 공개 구현 3곳의 실측을 기준으로 맞췄고, 첫 실행의 점검표(받은 건수/총건수·상태)로 실제 API 와 일치하는지 확인됩니다.
- 최종 기준은 입주자모집공고 원문입니다.
